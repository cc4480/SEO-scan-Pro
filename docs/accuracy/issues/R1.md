## New defects

### N-01 Offline fallback after a failed AI parse skips the fact-checker and measured scoring
- Site / finding: 07-stripe, all (scoreMethod undefined, qa undefined).
- Symptom: when DeepSeek's reply fails to parse, the user gets the canned offline report with scores from fixed formulas, unchecked.
- Evidence: event log `using the OFFLINE generator instead`; `lib/deepseek.ts` catch branch returns `generateSimulatorReport(crawl)` directly, whereas the no-API-key branch (line ~40) wraps it in `finalizeReport(...)`.
- Root cause: `lib/deepseek.ts` ~line 215.
- Proposed fix: wrap the fallback in `finalizeReport` as the other branch does, and in the user-visible report state clearly that it is a rule-based fallback. Pair with A-06 (tolerate trailing text after the JSON).
- Related: A-06.

### N-02 Offline generator writes claims that are unsupported or false
- Site / finding: 07-stripe 1 to 5, executive summary, aeoAssessment, competitorComparisonText.
- Symptom: "crawlability ... significantly improved" (all crawlers/sitemap/llms fine), "Introducing Schema.org structured models" (7 types present), "compressing static assets" (not measured), "Excellent" direct-answer friendliness and `voiceSearchOptimized: true` from `h2>2` / `h3>1`, richSnippetEligibility listing ContactPoint/Place/PostalAddress/ImageObject, competitor text "holds solid keyword density levels but trails premium competitors" (no data), "exceed 2026 search speed standards" (invented).
- Evidence: `lib/deepseek.ts` `generateSimulatorReport` lines ~225-462 vs the 07 payload (ttfb 276 ms, LCP 956 ms, CLS 0, 7 JSON-LD types, 13 crawlers 200, sitemap and llms.txt found).
- Proposed fix: make the executive summary, aeoAssessment and competitor text conditional on the facts (or drop them in fallback mode); drop "slow" unless LCP > 2.5 s or TTFB > 800 ms; remove the filler "Strengthen Answer optimization" fix and the invented standard; stop treating `alt=""` as missing (A-08).
- Related: A-06, A-08, A-13.

### N-03 Offline generator labels a 1.1 s load "critical / slow"
- Site / finding: 07-stripe 2 and 4.
- Symptom: `loadTime > 600` is critical and performance score is `100 - load/30`, although LCP is 956 ms and CLS 0.
- Root cause: hard-coded 600 ms threshold on the full load time in `generateSimulatorReport`.
- Proposed fix: use LCP/TTFB thresholds (Core Web Vitals) as the measured scorer does.
- Related: A-13.

### N-04 Simulated scan: real, measurable facts are discarded and placeholder numbers shown beside them
- Site / finding: 05-nytimes 12, 2, 6.
- Symptom: robots.txt was read (200, 8.5 KB) and explicitly disallows GPTBot, ClaudeBot, CCBot, Claude-SearchBot, ChatGPT-User and dozens more, but the report says per-crawler access is unknown and recommends confirming AI crawlers are allowed; also recommends llms.txt to a site that prohibits AI use.
- Evidence: curl of `https://www.nytimes.com/robots.txt` (browser UA) shows `User-agent: GPTBot / Disallow: /`, etc.
- Proposed fix: for `isSimulated`, either emit only the real measurements (robots, sitemap, llms, headers) as findings and nothing else, or parse robots.txt for named AI agents and report the policy. Also never offer "publish llms.txt" when robots.txt disallows AI agents by name (A-04).
- Related: A-04, A-01.

### N-05 Simulator placeholder is built from a bad brand name and malformed URLs
- Site / finding: 05-nytimes 4, 8.
- Symptom: brand "Www" (from `www.nytimes.com`), links `https://www.nytimes.com//about`, `twitter.com/www`.
- Root cause: `lib/crawler.ts` simulated crawl (~line 900-940) takes `host.split('.')[0]`.
- Proposed fix: moot if A-04 removes placeholder findings entirely; otherwise strip `www.`.
- Related: A-04.

### N-06 Fact-checker removed a TRUE claim because a nav label was read as a pricing section
- Site / finding: 08-vercel (removed "no visible pricing section ... reason: the page already has a pricing section"), fix 6 survived with contradictory text.
- Evidence: homepage text has "Pricing" only in header/footer links; `prices: []`; JSON-LD Offer price 0 with no on-page price.
- Root cause: `visibleSections.pricing` from navigation labels (A-05), consumed in `lib/audit/contradiction.ts` / `finalize.ts`.
- Proposed fix: fix A-05; and make the checker act consistently on the same claim whether it appears in a critical issue or a fix.
- Related: A-05.

### N-07 Checker removes a correct hreflang suggestion with a false reason; summary calls a multilingual site "single-language"
- Site / finding: 10-mdn (executive summary, removed item "Add hreflang only if MDN ships localized variants").
- Symptom: reason "no alternate-language versions were found" but the homepage markup has a 9-locale language switcher (`/de/ /es/ /fr/ /ja/ /ko/ /pt-BR/ /ru/ /zh-CN/ /zh-TW/`, `/de/` returns 200) and no `hreflang` tags. Summary says "acceptable for a single-language page".
- Root cause: "alternate versions" inferred only from hreflang tags themselves (circular); `multiLanguage: false` in signals.
- Proposed fix: detect locale-switcher links (language-code path links) in `contentSignals`; when found without hreflang, report the gap instead of suppressing it.
- Related: A-05, A-10.

### N-08 Raw-link count includes anchors inside `<template>` / web-component markup
- Site / finding: 10-mdn 8.
- Symptom: raw 169 vs JS-off DOM 160 (158 non-hash); report invents a cause ("conditionally hidden navigation or tracking links") and recommends removing server output.
- Evidence: reproduced with JS-off puppeteer; extra anchors are language-switcher links inside Lit `<template>`.
- Root cause: regex over source in `lib/audit/collect.ts` (raw side) does not strip `<template>`.
- Proposed fix: strip `<template>`/`<noscript>`/comments before counting; and the model prompt should not speculate about causes of small deltas.
- Related: A-10.

### N-09 Social-card advice ignores the declared image size
- Site / finding: 10-mdn 7.
- Symptom: tells MDN to switch `twitter:card=summary` to `summary_large_image` and a 1200x630 image, but the page declares `og:image:width/height` 1024x1024 (a square logo), which is the right fit for `summary`.
- Proposed fix: only suggest the large card when the declared image aspect ratio is about 1.91:1, or when image size is unknown, say so. Page uses `name="og:*"` rather than `property="og:*"`, which could be flagged instead.
- Related: A-13.

### N-10 robots.txt `Content-Signal` ignored while the report calls an allow-all policy "optimal for training crawlers"
- Site / finding: 08-vercel 9 (and the executive summary).
- Evidence: `https://vercel.com/robots.txt` begins `Content-Signal: search=yes, ai-input=yes, ai-train=no`.
- Proposed fix: parse Content-Signal and mention it; do not praise training access when the site opts out of training.
- Related: A-02.

### N-11 AEO recommendations suggest schema that cannot be implemented as stated
- Site / finding: 09-react-dev 5 and aeoAssessment, 10-mdn 4.
- Symptom: `WebSite` with `SearchAction` for a site whose search is a client-side widget with no search URL; "eligible for sitelinks search box" (retired by Google); BreadcrumbList for the root page.
- Proposed fix: prompt guidance in `lib/deepseek.ts`: no SearchAction unless a search URL is present in the payload; drop sitelinks search box claims.
- Related: A-07.

### N-12 Model invents what images and headings represent
- Site / finding: 09-react-dev 6; 08-vercel 7.
- Symptom: "video thumbnails" for avatars whose cited headings are code-sample file names; "product-area headings" that are footer link groups; the example alt text is invented.
- Proposed fix: constrain the prompt: only describe images from the `images.list` data (src, alt); do not infer purpose from unrelated headings.
- Related: A-07, A-08.

### N-13 Ground-truth tool defects (belongs to A-12)
- Ground `og` parsing reads only `property=`, so MDN (`name="og:*"`) shows empty values.
- Ground JS-off load returns status 304 for vercel and react.dev (conditional request / cache), so `noJs` words are unreliable there.
- Ground `visible words` via `innerText` undercounts pages that use `content-visibility`/lazy sections (vercel 134 vs ~332 after scrolling) without a scroll step.
- Summary of 07: scanner saw 42 images and ground 40 (scanner viewport gets a page variant); not a scanner bug.

### N-14 Minor: scoring penalty not surfaced; wrong locale count
- 09-react-dev: score breakdown deducts 6 for "no sitemap found" but no finding mentions it; summary says "8 locales with x-default" for 7 locales plus x-default.
- Related: A-13.
