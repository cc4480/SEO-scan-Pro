# R2 review: sites 11-shopify, 12-amazon, 13-nasa, 14-gov-uk, 15-hacker-news

## Register issues confirmed

- A-08 (alt="" counted as missing, wording "no alt attribute"): 11, 12, 13, 14 (all 15 shows true missing attributes on spacer gifs, minor).
- A-09 (hidden text in word counts; verified with live DOM walk of display:none text): 11 (343 words of 1,118), 13 (970 of 1,633), 14 (271 of 854).
- A-02 (single transient 429 = "refused"; spoofed-UA refusals): 13 (Bytespider 429 not reproducible in 5 later requests), 15 (419 for spoofed Googlebot/Bingbot/Applebot/GPTBot/ClaudeBot/... UAs).
- A-03 (challenge/interstitial audited as the site): 12 (raw-fetch path; see N3).
- A-10 (raw vs JS-off disagreement): 12 (0 vs 635), 11/13/14 (hidden text inflates raw words).
- A-12 (ground-truth robots false positive): 12, 14 (`Disallow: /` belongs to other crawlers' groups).
- A-13 (severity inflation): llms.txt, missing JSON-LD, OG tags, headers, heading counts shown as critical on 12, 13, 14, 15.

## New defects

### N1. Broken-link probe: undecoded `&amp;` and bot-wall statuses reported as broken (12, finding 5/10)
- Symptom: "two 404s (registration and sign-in URLs) and one 503": all three are not verified broken.
- Evidence: results `brokenLinks[].href` contain `&amp;`; live, the sign-in URL returns 302 when decoded and 404 only with `&amp;`; register answered 503 (bot wall) to me; `/gp/yourstore` answered 200 to me and 503 to the scanner.
- Root cause: link list hrefs were not entity-decoded before probing (current `findTags/parseAttrs` decodes, so probably fixed; needs a regression test on the probe path), and 403/429/503 from a site with bot defences are treated as "broken".
- Fix: decode hrefs; treat 401/403/429/503 (and anything with a bot-challenge header) as "unverifiable", never "broken"; re-probe once before reporting.

### N2. `<meta name="title" property="og:title">` is read by `name` only (14, findings 4 and 10)
- Symptom: GOV.UK has og:title and og:description; the scanner reports them empty and the report raises a critical issue and a high fix.
- Evidence: `curl` shows `<meta name="title" property="og:title" content="Welcome to GOV.UK">` and `<meta name="description" property="og:description" ...>`; ground `og.title`/`og.description` set; results `social.ogTitle/ogDescription` empty.
- Root cause: `lib/crawler.ts` meta loop: `const name = (attrs.name || attrs.property || '').toLowerCase()` plus the `seenMeta` set; only one key per tag. Still present in the current code.
- Fix: process `name` and `property` as two independent keys (a tag can set both); add regression test with that exact tag. Relates A-14 (same loop).

### N3. Raw (no-JS) fetch and crawler probes accept a 200/202 interstitial as the page (12)
- Symptom: raw words/links = 0; two criticals and a high fix tell the owner their site is empty without JavaScript. Crawler probes record 200 "received the page" for a 2,185-byte challenge.
- Evidence: results `rawBytes: 2185`; curl with the scanner's browser UA returns `<meta http-equiv="refresh" content="5; URL='/?bm-verify=...'">` (title `&nbsp;`, 0 words); the same URL with other UAs returns 700 KB, and a real JS-off load has 635 words. Amazon also serves a captcha page ("To discuss automated access to Amazon data...", 3.7 KB) and an empty HTTP 202.
- Root cause: `lib/audit/collect.ts` raw fetch has no interstitial detection; A-03's challenge detector (rendered path) is not applied to the raw response or to bot probes.
- Fix: detect challenge responses on raw fetch (tiny body, meta refresh to a verify token, 202 with empty body, captcha markers); then report "raw HTML could not be read" and suppress the JS-dependence critical/fix and the score penalty. Relates A-03, A-10.

### N4. `robotsAllows:false` misread as "not explicitly allowed" (12, findings 7 and 12)
- Symptom: advice to "add explicit allow rules" for crawlers that robots.txt explicitly disallows (Amazon disallows GPTBot, ClaudeBot, CCBot, Bytespider, PerplexityBot, Perplexity-User, Claude-SearchBot, Claude-User, ChatGPT-User); also says Googlebot/Bingbot/Applebot are "explicitly allowed" when they have no group.
- Evidence: robots.txt groups with `Disallow: /`; `botAccess.results[].robotsAllows` is false.
- Root cause: the model only gets a boolean; "false" is ambiguous (disallowed vs no rule). `lib/audit/botAccess.ts` / `deepseek.ts` / `finalize.ts`.
- Fix: expose `robotsDisallows` (explicit group) per crawler; add a checker rule that removes any "allow crawler X" finding when X is explicitly disallowed and reports it as a policy statement ("blocked by robots.txt: owner's choice") instead. Relates A-02, A-13.

### N5. Relative hrefs without a leading slash classified external (15, finding 13)
- Symptom: "1 internal and 224 external links" (real ~192 internal), and a false conclusion that the page is outbound-only.
- Evidence: HN anchors are `item?id=`, `user?id=`, `hide?id=`; ground `internalAnchors` 192; old code resolved only hrefs starting with `/` or `.`.
- Root cause: link loop in `lib/crawler.ts` (the current code uses `new URL(href, url)` and looks fixed). Needs a regression test with slash-less relative hrefs and `?query` only hrefs.
- Relates A-11.

### N6. Bot probe log and report disagree about non-2xx statuses outside {401,403,406,429} (15)
- Symptom: scan log says "all 13 crawlers received the page" while 8 got HTTP 419; report calls them blocked.
- Evidence: `botAccess.results` status 419, `blocked:false`; log line above; finding 1.
- Root cause: `lib/audit/botAccess.ts` `REFUSAL` set; the report ignores `blocked`.
- Fix: classify any non-2xx different from the baseline as "refused" (inconclusive for IP-verified crawlers, per the A-02 contract) and use one wording everywhere; never say "cannot be indexed" from a spoofed-UA probe. Relates A-02.

### N7. 429 treated as a block and not re-tested (13, finding 6)
- Symptom: Bytespider "refused" from a single 429; 5 later requests with the identical UA returned 200.
- Evidence: scanner and ground both saw 429; curl x5 over 15 s got 200 (nginx, `x-cache: HIT`). Fix text: "Bytespider (HTTP 429) were refused" (grammar).
- Root cause: `REFUSAL` includes 429 (rate limit), single attempt. Fix: re-probe a refusal once after a short delay; treat 429 as rate-limited/inconclusive; fix pluralisation. Relates A-02.

### N8. Model invents image identities in remediation text (14, finding 9)
- Symptom: "the GOV.UK crown logo, the Open Graph preview image" when the 4 images are promo images and an app icon.
- Evidence: `images.list` src names (find-a-job, national-insurance-featured, cost-of-living-featured, govuk-app-icon).
- Root cause: the prompt gives counts, not the image list; the model fills examples. Relates A-07.
- Fix: pass up to ~10 image src basenames, or forbid example identities that are not in the evidence (checker rule in `contradiction.ts`).

### N9. Schema subtype blindness: "lacks Organization" when Corporation is present (11, finding 7)
- Symptom: tells the owner to add Organization markup that exists (as Corporation, a schema.org subtype).
- Evidence: results `schema.entities` Corporation with logo, sameAs, contactPoint.
- Root cause: type comparison is by exact name in the prompt/checker. Fix: normalise through a small subtype map (Corporation, LocalBusiness, NGO, ... => Organization) before stating a type is missing. Relates A-07.

### N10. "No testimonials/reviews" asserted while customer stories are on the page (11, finding 10)
- Symptom: recommends adding case studies to a page that has them.
- Evidence: live text "Jackie Prince launched Guests on Earth ... Now it's a $4M+ business", "Our Place grew...", Mattel, "What winning looks like" cards; `signals.sections.reviews=false` only detects ratings/review markup.
- Root cause: `lib/audit/contentSignals.ts` reviews signal is too narrow; the model extends it to testimonials. Fix: restrict the claim to "no ratings or Review markup" or add a customer-story signal ("customer stories", "case study", "how X uses"). Relates A-05/A-07.

### N11. Generic navButtons advice with no evidence (14, finding 14)
- Symptom: "audit the 4 nav buttons" although the buttons are cookie, menu/search toggles and feedback and the links exist in raw HTML (rawLinks = renderedLinks).
- Evidence: live button list; no-JS DOM keeps 22 menu links.
- Root cause: `navButtons` counts all buttons in nav-ish containers; model turns it into a finding. Fix: only allow a navButtons finding when rawLinks is much lower than renderedLinks (or navAnchors in raw < rendered).

### N12. Outdated Google feature claims (11 finding 3; 14 finding 15; 15 finding 8)
- Symptom: "FAQ rich results" eligibility (Shopify), SearchAction/sitelinks search box (GOV.UK, HN) presented as benefits; FAQ/HowTo rich results are not shown for ordinary sites and the sitelinks search box was retired in 2024.
- Root cause: model prior knowledge, not constrained. Fix: add a deny-list of retired features to the prompt and checker (`contradiction.ts`), and downgrade FAQ/SearchAction findings to low/"AI answer engines only". Relates A-13.

### N13. Benefit claims for llms.txt unsupported (12, 13)
- Symptom: "improving retrieval accuracy in ChatGPT Search, Perplexity, Gemini", "helps AI crawlers understand ...", priority high/critical.
- Evidence: nothing the tool measured shows any crawler reads llms.txt. Fix: cap llms.txt at low priority, wording "optional, not yet read by major engines" in the prompt. Relates A-13.
