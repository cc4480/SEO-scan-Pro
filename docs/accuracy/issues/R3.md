## R3-01 The renderer uses Puppeteer's default 800x600 viewport; responsive pages change

- Site/finding: 18-nike critical 9 and fix 16 (CLS 0.192), fix 13 (H2 list), sheet H2 8 vs 13; 20-airbnb fix 6 (LCP 3,880 ms); 16-reddit image count.
- Symptom: measurements and findings describe a tablet/mobile-width layout, not what a desktop visitor gets.
- Evidence (same UA, my own puppeteer, networkidle2): nike default viewport CLS 0.185 / LCP 13,092 ms / 8 H2s; viewport 1366x900 CLS 0.054 / LCP 3,132 ms / 13 H2s (the ground truth, which sets 1366x900, reports 13). airbnb: 800px LCP 6,780 ms, CLS 0.085, 1,506 words; 1366px LCP 2,384 ms (good), CLS 0.045, 981 words. reddit: 125 images at 800px vs 141-142 at 1366px.
- Suspected root cause: `lib/crawler.ts renderPage` never calls `page.setViewport`.
- Proposed fix: set a desktop viewport (e.g. 1366x900, dpr 1) for the primary render; if mobile numbers are wanted, run a second explicit mobile pass and label the findings "mobile" or "desktop". At minimum state the viewport next to lab vitals.
- Related: A-11, A-09.

## R3-02 Ground-truth tool captures partially hydrated pages

- Site/finding: 16-reddit sheet (ground 26 images / 474 words / 95 links vs scanner 125 / 2,296 / 199), 20-airbnb (43 vs 51 images).
- Symptom: the sheet flags large "mismatches" that are the ground tool's error. Re-measured live with the ground tool's own UA and viewport: reddit 141 images, 2,795 innerText words, 201 links; airbnb 51 images, 981 words. Reddit's feed lazy-hydrates after the JS challenge; the ground run's `bodySample` shows only the first posts, and `finalUrl` is still the `?js_challenge=1&jsc_token=...` URL.
- Suspected root cause: `scripts/audit-corpus/ground.ts` measures right after `networkidle2`; Airbnb never goes idle and Reddit streams the feed.
- Proposed fix: after goto, poll `document.body.innerText.length` / img count every 500 ms until stable for 2 s (cap 15 s), and record the stable-time; record `finalUrl` after challenge.
- Related: A-12.

## R3-03 `robotsBlocksAll` is read from the `*` group only; named crawlers with their own rules are ignored

- Site/finding: 17-linkedin critical 1, fix 7, score "-40 robots.txt disallows the whole site".
- Symptom: "robots.txt disallows every crawler from the entire site ... no search engine or AI crawler can index the logged-out pages". The real file (120 KB, fetched live) has about 60 named groups. Googlebot, Bingbot, Applebot, OAI-SearchBot and Claude-SearchBot get partial Disallow lists (and `Allow: /`), only the unnamed crawlers (CCBot, Bytespider...) and the listed AI agents (GPTBot, ClaudeBot, ChatGPT-User, PerplexityBot, Claude-User...) get `Disallow: /`. The scan's own `botAccess.robotsAllows` already says true for the five search bots, contradicting the headline.
- Suspected root cause: `lib/audit/robotsRules.ts` / robots parsing in `lib/crawler.ts` (the `robotsBlocksAll` flag) and the `scoring.ts` 40-point penalty.
- Proposed fix: set the flag only when no named search crawler is allowed; otherwise report "unnamed crawlers are blocked; named crawlers are governed by their own rules". Scale the penalty to what is actually blocked.
- Related: A-01, A-12.

## R3-04 "Navigation built from buttons" counts language pickers, search and cookie buttons

- Site/finding: 17-linkedin fix 6 and score "-6 navigation uses buttons instead of links"; 19-ikea critical 2 and fix 5; 18-nike critical 6.
- Symptom: "37 buttons but only 19 real links ... crawlers follow links; destinations invisible". The 37 LinkedIn buttons are all footer language-picker buttons (Arabic, Bangla, ...) plus one "Language"; the real navigation is anchors and the raw HTML already holds 158 links (the scan's own `rawLinks`). IKEA's buttons are USEnglish, store, Clear search, Search, Open navigation menu, Cookie settings (10 at 1366px, 14 at the scanner's width); raw links 185.
- Suspected root cause: `navButtons` = every `button` in nav/header/footer (`lib/audit/collect.ts` or `htmlFacts.ts`) and the checker in `finalize.ts` treats a ratio of buttons to anchors as a crawl defect.
- Proposed fix: ignore buttons that carry no destination semantics (search, menu toggle, cookie, language, `aria-haspopup` controls) and suppress the finding when raw links are already >= 80% of rendered links.
- Related: A-05 (same family: structural label read as a claim about content).

## R3-06 HTTP 999/403/429 from a link probe are scored as broken links

- Site/finding: 17-linkedin critical 3 and score "-6, 2 broken link(s) in the sampled 15".
- Symptom: a "critical" and a score penalty for links the report itself says are "not broken pages" (anti-bot response). Live check: `/jobs/search?trk=...` returns 200 to a Chrome UA (999 only to the scanner's probe); `/pub/dir/+/+` returns 999.
- Suspected root cause: the link prober in `lib/crawler.ts` counts any status >= 400 or 999 as `brokenLinks`; `scoring.ts` subtracts 3 per entry.
- Proposed fix: treat 999, 401, 403, 429 (and 5xx on a single probe) as "unverified", exclude from the broken count and the score, retry once with a browser UA.
- Related: A-02.

## R3-07 A JavaScript challenge interstitial is recommended for server-side rendering

- Site/finding: 16-reddit critical 1, 5, fix 12 and scoring "-20 almost no content without JavaScript".
- Symptom: raw HTML (8,397 bytes, `<title>Reddit</title>`, a form submitted by script) is the bot-challenge page; the report tells Reddit to "server-render the headline, main sections, FAQ and navigation". Finding 9 correctly names the challenge, but the other findings and the score do not.
- Suspected root cause: no detection of the challenge in `collect.ts` raw fetch (`pageKind` contract from F-MEASURE should cover rendered; the raw side needs the same).
- Proposed fix: when the raw response matches a challenge signature (jsc_token / js_challenge / "Just a moment" / tiny body with a self-submitting form), mark the raw comparison inconclusive, drop the JS-dependence finding and score, and emit one measured finding "the site serves a JavaScript challenge to non-browser clients".
- Related: A-03, A-10.

## R3-08 "Page weight" and "transfer" are the serialized DOM size

- Site/finding: 16-reddit fix 19 ("homepage transfers 924.1 KB"), 19-ikea fix 10 ("page size 1,962.8 KB ... transfer-bound"), 18-nike score "-5 page weighs 1,597 KB", 20-airbnb.
- Evidence: `pageSizeKb` equals `page.content().length / 1024` (reddit html 923,811 chars in my run = 924 KB). It is the size of the rendered DOM text, not bytes on the wire (compressed HTML plus images/JS). IKEA's "86% of load time is network and transfer" is also an inference from `1 - ttfb/load`; load includes parse, script and image time.
- Proposed fix: rename to "rendered HTML size" in prose and the prompt, stop scoring it as weight, or measure transferred bytes from `Network` events. Remove the "transfer-bound" inference.
- Related: none.

## R3-09 Offline report (20-airbnb): hard-coded claims, scores that bypass measurement

- Site/finding: 20-airbnb all findings, executive summary, aeoAssessment, competitor text, scores.
- Symptom (confirmed from the scan's event log and `lib/deepseek.ts generateSimulatorReport`): `scoreMethod` is undefined and there is no `scoreBreakdown` or `qa`, so the five scores (71 / 93 / 30 / 95 / 65) are the offline formula, not measured ones: content 30 is the floor of `95 - 4 x 51 alts`; performance 65 = `100 - 1050/30`; aeoGeo 95 = `70 + 15 (has JSON-LD) + 10 (more than 2 H2)` while 12 of 13 crawler probes were refused and the page has 107 raw words vs 1,873 rendered.
- Unsupported or wrong text: "Detected slow page generation delay of 1050ms" (fixed 600 ms threshold; 1,050 ms with 208 ms TTFB is fast); "Response times exceed 2026 search speed standards" (no such standard exists); "Introducing Schema.org structured models ... will immediately amplify index ranking" (the page already carries WebSite/SearchAction JSON-LD; the promise is unsupported); "directAnswerFriendliness: Excellent. Structuring topics with clean subheadings..." (a constant, no text was read); `generativeFriendlinessScore` 85 is `hasJsonLd ? 85 : 55`; `voiceSearchOptimized: true` is `h3.length > 1`; "competitorComparisonText: holds solid keyword density levels but trails premium competitors who leverage comprehensive structured sitemaps and responsive media compressions" (no competitor or keyword data was gathered; Airbnb has a sitemap index); "Audit image templates and populate [alt] with contextual keywords" encourages keyword stuffing; AEO tips "Organize FAQ blocks ... Configure clean Schema schemas mapping specific business locations" are generic and not derived from the page; the agent prompt repeats all of this as tasks. It omits the real findings: 12 of 13 crawler UAs refused, the 107-word raw response, the 18 images with no alt attribute, hreflang.
- Suspected root cause: `generateSimulatorReport` and `finalizeReport` not applied (or not scoring) on the fallback path in the run that produced this file (`qa`/`scoreMethod` empty); the generator keeps editorial constants.
- Proposed fix: on fallback, run the same measured scoring and checker as the AI path, emit only measured findings, delete the constants (AEO prose, competitor text, executive-summary promise, "2026 standards"), and label the report "generated without the AI model" in the UI.
- Related: A-06, A-04 (fabricated filler), A-13.
