## R4-01 Redirect "hops" counted as chain length

- Site/finding: 24-craigslist critical 1 and fix 10; 21-cloudflare fix 13.
- Symptom: "three-hop redirect chain" for www.craigslist.org -> geo.craigslist.org -> /area/laredo; Cloudflare "single-hop redirect chain" when there is no redirect.
- Evidence: the scan's own event says "2 redirect hop(s)" (cloudflare: "no redirects"); curl shows two 302s. redirectChain lists URLs including the start URL, and the AI reads its length as the hop count.
- Suspected root cause: the prompt/evidence passes `redirectChain` (URLs) without an explicit hop number (`lib/deepseek.ts` evidence block / `lib/reportEvidence.ts`).
- Proposed fix: pass `redirects: chain.length - 1` explicitly and name it in the prompt; add a finalize check that "N hops" in text equals chain.length - 1.
- Related: none.

## R4-02 Section signals matched in editorial headlines and donation prices

- Site/finding: 25-guardian signals faq:true, reviews:true, features:true, pricing:true; checker removal "Enhance Direct Answer Friendliness (page already has a faq section)".
- Symptom: a news homepage is credited with an FAQ section, visible reviews and pricing.
- Evidence: the faq signal matched the bare word "questions" in the headline "...then two magic questions set me free"; reviews matched ~13 book/TV/film review headlines; pricing came from "$10 per month" in the Support banner. The live DOM has no FAQ.
- Suspected root cause: `lib/audit/contentSignals.ts`: `faq` regex includes bare `questions`; `reviews` matches the word in any heading; `pricing: prices.length > 0` accepts any dollar amount.
- Proposed fix: drop bare `questions` (require "faq|frequently asked|common questions"), require a heading to be (almost) only the keyword, restrict to headings of top-level sections (not article cards); require a price near a plan/pricing context. Also gate signals when the page is a feed of articles.
- Related: A-05.

## R4-03 A short or different raw (no-JavaScript) response is trusted; entire "JS-only" narrative follows

- Site/finding: 23-python critical 1, fixes 5 and 6 and checker additions "JavaScript-dependent content", "schema only after JavaScript".
- Symptom: raw fetch recorded 21,035 bytes, 164 words, 0 links, 0 schema; the real page (curl, 3 UAs, node https x6) is 52,966 bytes, 205 links, JSON-LD in raw HTML. Rendered DOM was 61 KB. Ground JS-off load: 559 words, 204 anchors.
- Evidence: first 21,035 bytes of the real page already hold 72-81 anchors (so not simple truncation); not reproducible on re-request.
- Suspected root cause: `lib/ssrfGuard.ts requestOnce` resolves on `close` as well as `end` and ignores `res.aborted` / `res.complete`, so a cut-off body is accepted as complete; `lib/audit/collect.ts` then takes it at face value.
- Proposed fix: reject (or flag `truncated`) when `!res.complete` or content-length mismatches; in collect.ts retry once and, when raw bytes are far smaller than the rendered DOM and raw links are 0, mark the raw comparison inconclusive instead of emitting the "most content only after JavaScript" warning and findings; cross-check with a second raw fetch.
- Related: A-10.

## R4-04 HTTP 999 (and other anti-bot codes) counted as a broken link

- Site/finding: 23-python critical 4 and fix 8 (LinkedIn 999).
- Symptom: "One broken external link ... returns status 999", critical, with advice to add rel="nofollow".
- Evidence: 999 is LinkedIn's bot-block code; my HEAD with a browser UA got a plain 301. The same run showed Cloudflare's 403s on dash.cloudflare.com correctly NOT counted as broken, so the rule is inconsistent.
- Suspected root cause: broken-link probe in `lib/crawler.ts` (~line 551, the 404/410/5xx classifier) treats unknown 4xx/9xx as broken.
- Proposed fix: broken = 404/410/5xx only; 999, 401, 403, 429, "no answer" are "could not be checked". Never rate it critical.
- Related: A-02 (bot-blocked probes).

## R4-05 Checker removes a fix with an unrelated reason; the matching critical stays

- Site/finding: 23-python ("Add an llms.txt File" removed because "the page already has a about section"); also 24-craigslist (alt-text and FAQPage fixes removed but critical 5 and 6 remain).
- Symptom: the removal reason has nothing to do with the recommendation, and the critical issue of the same topic is still shown, so the report contradicts itself (critical 3 says add llms.txt, fix list has none).
- Evidence: python llms.txt fix text contains "about" as a preposition ("guide AI models about ..."); `SECTION_TERMS.about = ['about']` matches it via `asks(text,'about')`.
- Suspected root cause: `lib/audit/contradiction.ts` section-term match is a bare word; and `finalize.ts` applies the contradiction check to recommendedFixes only, not to criticalIssues.
- Proposed fix: match about/contact only when the fix is about adding such a section (e.g. "about page", "about section"), skip when the text's subject is another artefact (llms.txt, sitemap, schema); run the same contradiction filter over criticalIssues so both lists agree.
- Related: A-05, A-13.

## R4-06 Content-Security-Policy-Report-Only ignored

- Site/finding: 23-python fix 9 ("CSP missing ... start with a report-only policy").
- Symptom: the site already sends `content-security-policy-report-only` (verified live); the fix recommends doing exactly that.
- Suspected root cause: `securityHeaders` in `lib/crawler.ts` only records `content-security-policy`.
- Proposed fix: record `cspReportOnly`; if present say "CSP is report-only (not enforced)" instead of "missing".
- Related: none.

## R4-07 Geo-routing redirect advised as a defect

- Site/finding: 24-craigslist fix 10 ("high": redirect directly with a single 301 to /area/laredo).
- Symptom: the root URL 302-redirects by visitor location by design; the advice is impossible and the severity "high".
- Evidence: curl: 302 geo.craigslist.org, 302 /area/laredo; the final URL depends on the requester's IP.
- Suspected root cause: the redirect finding has no notion of temporary (302/307) location-based redirects.
- Proposed fix: include the status codes in the evidence; when hops are 302/307 to a geo/locale host, either skip or downgrade to info with "location/language based redirect".
- Related: R4-01.

## R4-08 FAQPage and BreadcrumbList advised without matching visible content

- Site/finding: 22-mozilla fixes 6 and 7.
- Symptom: FAQPage recommended for marketing H3s ("A Rebel Alliance?", "Open Source AI Is Winning"); BreadcrumbList "Home > en-US" for the homepage.
- Evidence: the headings are not Q&A pairs; a one-item breadcrumb on the home page has no value; FAQPage markup must reflect visible questions and answers.
- Suspected root cause: `lib/deepseek.ts` prompt lacks "only recommend FAQPage if visible Q&A exists / no breadcrumbs on the homepage"; nothing in finalize.ts checks it.
- Proposed fix: prompt rule plus a finalize filter: drop FAQPage fixes when `signals.sections.faq` is false and no heading ends in "?" followed by a paragraph; drop BreadcrumbList on a root path.
- Related: A-07, A-13.

## R4-09 Evidence-light "critical" for absent images on text-first pages

- Site/finding: 24-craigslist critical 5 ("no images limits visual engagement") and critical 8 (word count "thin").
- Symptom: a presumption that every page needs images and 1,000 words becomes a critical issue.
- Suspected root cause: prompt/scoring treat imagesCount 0 and low word count as defects regardless of page type.
- Proposed fix: never "critical" for these; only mention when the page type (content article/product) warrants it, or when also correlated with a real defect. Related: A-13.
